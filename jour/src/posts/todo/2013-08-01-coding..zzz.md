#Coding Standards

##Component Naming Conventions

* Descriptive name, followed by component type.  For example a label displaying the program version information will be renamed to "ProgramVersionLabel" from "Label4".
* Although it is possible to give units names that are more than 8 characters long, keep them at or below 8.

##Source Code Commenting

* Comments will be liberally placed throughout the code, preferably at the end of a coding session.  This should preserve the developer's flow of coding while leaving time at the end to add comments before the purpose of each code block is forgotten.
* Each conditional statement (If, While, Repeat) will be suffixed with a comment containing the condition after the final END.
* Each procedure and function will be suffixed by its name after the final END.

##Indenting

Consistent indenting style will be used, even at the expense of longer source code lines.

##Initiation and default
* Wherever possible, set every TForm’s Scaled property to FALSE.

##component
* Use third-party components be­fore hand-coding new components. Third-party components will probably do more, be of higher quality, and cost less when labor expenses are considered.
* Use native components before using third-party components if the component will do the job. The idea is to be dependent on as few vendors as possible.  Also, every installation will have the standard components; third-party components will have to be installed manu­ally.
