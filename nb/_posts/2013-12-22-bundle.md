[Bundler](https://bundler.io/docs.html)
can install dependencies in the project
folder, it can help you avoid permissions issues you might otherwise run into.

>Bundler provides a consistent environment for Ruby projects by tracking and installing the exact gems and versions that are needed.

>Bundler is an exit from dependency hell, and ensures that the gems you need are present in development, staging, and production. Starting work on a project is as simple as `bundle install`.

It will take note of the dependencies which have been resolved and save them to a `Gemfile.lock`.

Others work on the project can run `bundle install` and work with the exact same dependencies.

Another benefit of this is that if you have multiple versions of gems installed, you can have bundler use the correct version as specified in the Gemfile.

## Gemfile vs. Gemfile.lock

If you change your Gemfile, by running `bundle install` you will update your Gemfile.lock file.

If it's too slow, pass `--local` through which forces it to only use local gems to resolve its dependencies.

Others will be able to install the correct dependencies based on `Gemfile` and `Gemfile.lock`, which should both be checked in.

In version control, you'll want to ignore the `./vendor/` and `./.bundle/` folders.

Running `bundle update` by itself can be construed as dangerous that will update all the dependencies of your application. It's mainly dangerous if you don't have solid version numbers specified in the Gemfile.

## Configure Bundler Install Path

The advantage is that bundler will install gems within your project folder instead of the
location used by `gem install`.

Otherwise, bundler will install your dependencies to the location
used by `gem install`.

```sh
bundle config set --local path 'vendor/bundle'
```

This step is only required once per project. Bundler saves your config in
`.bundle/config`, so future gems will be installed to the same
location.

This command will add the gem to Gemfile and install it to
the `./vendor/bundle/` folder (or your default gem installation directory if you
didn't set a custom path).

```sh
bundle add jekyll
```

Now that Jekyll is installed, we can use it to create the scaffolding for our
site. We need the `--force` parameter because our folder isn't empty - it
already has some Bundler files in it. We run the `bundle install` separately
because Jekyll gets confused if the Gemfile already exists.

```sh
bundle exec jekyll new --force --skip-bundle .
bundle install
```

You should prefix commands with `bundle exec` so that Bundler
runs the version that is installed in your project folder.

## bundler install

### group

```ruby
group :development do
  gem 'sqlite3'
end

group :production do
  gem 'pg'
end
```

```sh
bundle install --without production # only install needed RubyGems
```
